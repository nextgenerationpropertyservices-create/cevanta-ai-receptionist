## Evidence and rollback

### Local request budget — CEV-RETELL-BUDGET-29 (implementation awaiting review)

The local opt-in handler bounds the complete raw-body read to5000ms from reader acquisition, rather than renewing a timer for every chunk. A monotonic elapsed check complements the timer so continuously available chunks cannot indefinitely evade it. Timeout returns408 request_timeout with persisted:false and bookingCreated:false. Request abort/stream failure returns generic400; oversized accumulated bytes remain413. Timer/listener cleanup runs on all reader paths. Incomplete streams are cancelled best effort; cancellation rejection is absorbed and a cancellation promise that never settles is not awaited. Locks are released best effort. No raw body or cancellation error is logged. Existing default-off and hard production-disable checks still run before acquiring a reader or starting a deadline. Five seconds is a local prototype resource budget, not the provider delivery timeout, hosted SLA or booking-duration policy.

This does not add a rate limiter or distributed concurrency guarantee. A local process semaphore/token bucket would reset on restart and permit each worker its own allowance; it would not stop upstream buffering or a fleet-wide flood. No trusted client key/forwarded-IP authority, deployment topology, shared limiter store or approved limits exist yet. Cookies, supplied tenant IDs and unverified provider fields must not become admission authority. Phoenix must assign an approved edge/global request+connection limit and retry/429 policy; Atlas/Quinn review shared state, trusted identity and distributed semantics before implementation. A separate Blake task can then add a per-instance bounded active-reader/backlog safeguard if the reviewed runtime needs it, releasing admission on success/timeout/abort/errors and rejecting excess requests before buffering. This is proposed design, not an implemented guarantee. Hosted bytes, logs, request-header limits and total infrastructure concurrency remain blocked.

Use fictional request identifiers and outcomes only. Never put real keys, callback URLs, customer details, transcripts or recordings in source, fixtures, reports or logs. No broad secret scan can prove that all outside infrastructure is clean; recorded evidence is limited to inspected paths and synthetic tests.

Rollback for this task removes only the offline inventory, tests and readiness docs. No database or provider state changes. Keep prototype opt-in unset and production guard intact. Later hosted tests require a separately approved shutdown/teardown plan and evidence that no operational callbacks/writers became connected. Morgan accepts only after Blake backend and Quinn security reviews; Atlas is needed before any new hosted architecture, tenant routing or durable receipt contract.
