# Invitation HTTP privacy and CSP contract

Date: 2026-10-28

Task: CEV-RELEASE-170B1

Status: architecture approved for implementation; no source, deployment, or hosted database change is included here

## 1. Decision

Use a **request nonce generated by the existing Next.js 16 `src/proxy.ts`** for invitation HTML. Do not use a bootstrap-only static hash as the primary policy: Next.js emits framework and streamed inline scripts whose contents are not a stable application constant, so hashing only the Cevanta bootstrap would either break rendering or pressure the implementation toward production `script-src 'unsafe-inline'`. Do not enable experimental SRI for this narrow repair.

The nonce design follows the installed Next.js 16 CSP guide:

1. Proxy generates a fresh unpredictable nonce for each `/invite` or `/invite/continue` request.
2. Proxy puts the same CSP in the upstream request header and downstream response header, and passes the nonce upstream only as `x-nonce`.
3. The invitation entry page is explicitly dynamic, reads `x-nonce` on the server, and gives that nonce to the audited early bootstrap `<script>`.
4. Next.js reads the request CSP and applies the nonce to its own framework/streaming scripts.
5. The exchange API uses a fixed document-denying CSP because JSON requires no script nonce.

No production invitation script policy may contain `unsafe-inline`. Development may add `unsafe-eval` only to `script-src` because the installed Next.js guide requires it for React diagnostics. This exception must be based only on `NODE_ENV !== 'production'` and must not appear in a production response.

## 2. Exact protected surfaces

The privacy boundary covers:

- `GET /invite`
- every `/invite/:path*` document, currently `/invite/continue`
- `POST /api/invitations/continuations`, including every success and failure response

The current proxy matcher already reaches these paths. Tests must prove that exact and nested invitation documents and the exact exchange API remain matched. Do not broaden the CSP to the public landing page or unrelated authenticated routes in this repair.

Keep the existing broad `config.matcher`; do not add invitation paths to its negative lookahead. Inside proxy, use these exact predicates before the Supabase refresh branch:

```text
invitation document = pathname === "/invite" || pathname.startsWith("/invite/")
invitation exchange = pathname === "/api/invitations/continuations"
```

Only the document predicate creates a nonce. Both predicates bypass Supabase session refresh. A lookalike such as `/invited`, `/api/invitations/continuations-other`, or an unrelated API route must keep its existing behavior. The API route's CSP is fixed by route/config headers and does not receive or need `x-nonce`.

`/invite` and `/invite/continue` must bypass the proxy's Supabase session refresh. The entry page must not wait on a provider call, and the continuation page performs its authoritative server-side identity check itself. The exchange API must also bypass proxy session refresh; the route and database command already derive the optional/current identity through the ordinary public Supabase session and enforce the same-origin contract. These bypasses do not weaken authorization.

## 3. Invitation document policy

For each invitation document request, proxy must create a fresh base64 nonce with at least 128 bits of cryptographic randomness. It must set the CSP on both:

- the cloned upstream request headers supplied through `NextResponse.next({ request: { headers } })`; and
- the downstream `NextResponse` headers.

It must not expose `x-nonce` as a separate response header, cookie, URL value, log field, or error value. The nonce will naturally appear only on allowed HTML script/style elements and inside that response's CSP.

Production CSP directives:

```text
default-src 'self';
script-src 'self' 'nonce-<request nonce>' 'strict-dynamic';
script-src-attr 'none';
style-src 'self' 'nonce-<request nonce>';
style-src-attr 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self';
connect-src 'self';
worker-src 'self';
manifest-src 'self';
media-src 'none';
frame-src 'none';
object-src 'none';
base-uri 'none';
form-action 'self';
frame-ancestors 'none';
upgrade-insecure-requests;
```

`style-src-attr 'unsafe-inline'` is intentionally limited to style attributes needed by the current Next image/UI output. It does not authorize inline scripts. No third-party origin is allowed by any directive.

Development may add `unsafe-eval` to `script-src` and `unsafe-inline` to `style-src`; production may not. Do not add analytics, pixels, third-party fonts, external images, frames, report collectors, or telemetry to the invitation surface.

Every invitation document response must also contain:

```text
Cache-Control: private, no-store, max-age=0
CDN-Cache-Control: no-store
Vercel-CDN-Cache-Control: no-store
Pragma: no-cache
Expires: 0
Referrer-Policy: no-referrer
X-Robots-Tag: noindex, nofollow, noarchive
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

The Vercel-specific cache header is defense in depth and may be consumed/removed by the platform before reaching the browser. Verification must inspect both the local Next production server and a later authorized preview; the browser-visible `Cache-Control` must never contain `public`, `s-maxage`, `stale-while-revalidate`, or `immutable`.

## 4. Page and bootstrap contract

`src/app/invite/page.tsx` must become explicitly dynamic and read the nonce with the async Next.js 16 `headers()` API. It passes only the nonce to `InvitationBootstrap`; it must not receive or render the fragment, request ID, token, continuation, email, tenant, role, or return URL.

`InvitationBootstrap` must render:

```tsx
<script nonce={nonce} dangerouslySetInnerHTML={{ __html: invitationBootstrapSource }} />
```

The existing ordering remains mandatory: the bootstrap is the first executable invitation-page element, and `history.replaceState` runs before parsing, fetch, visible invitation content, hydration effects, service-worker registration, or optional imports. The nonce change must not move this script behind `Brand`, status UI, or a client effect.

The page may treat a missing/malformed `x-nonce` as an integration defect, but tests must prove the production proxy always supplies a valid nonce. Do not add a query-token, `unsafe-inline`, or client storage fallback.

## 5. Exchange API policy

The API returns JSON and needs no executable content. Its fixed CSP is:

```text
default-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; sandbox
```

Every API success and failure response must include the same cache/referrer/robots/content-type/frame/permissions headers listed for invitation documents, plus the fixed API CSP. It must never emit CORS allow-origin headers. The continuation cookie contract remains unchanged.

Because the current global `next.config.ts` rule overwrote the route handler's `Referrer-Policy` in the actual production-server check, implementation must add **later, route-specific header rules** for `/invite/:path*` and `/api/invitations/continuations`. The route handler must also retain its own complete response-header set so direct handler tests and nonstandard adapters fail safely. For invitation HTML, CSP itself remains nonce-generated in proxy; do not put a static HTML CSP in `next.config.ts`.

The later `/invite/:path*` config rule repeats every static privacy header in section 3 but omits CSP. The later API rule repeats that same static set and adds the fixed API CSP. Proxy also applies the complete document set, including dynamic CSP, to its downstream invitation response. This deliberate duplication protects direct handlers/adapters while ensuring the final Next response cannot inherit the global `strict-origin-when-cross-origin` value.

## 6. Service-worker boundary

The existing service worker currently treats `/invite` as a public route and can fall back to cached `/` after a network failure. That would omit the early bootstrap while leaving the pasted fragment visible in browser chrome. `public/sw.js` must bypass every exact or nested invitation path before `event.respondWith`, just as it bypasses API/auth/private workspace routes:

```text
url.pathname === '/invite' || url.pathname.startsWith('/invite/')
```

No invitation document may be stored in Cache Storage or receive the public `/` offline fallback. The existing API bypass remains required. A service-worker regression test must positively assert the invitation bypass.

## 8. Required evidence

Implementation evidence must include:

1. Proxy unit tests for exact invitation documents/API, provider bypass, no body consumption, fresh nonces, upstream request CSP, downstream response CSP, and exact privacy headers.
2. UI tests for explicit dynamic behavior, nonce propagation to the first script, and no identifier/token rendering.
3. API tests covering the complete header set on both success and representative 4xx/5xx failures, no CORS, and unchanged cookie behavior.
4. Service-worker tests proving exact/nested invite paths bypass fetch interception and offline fallback.
5. Browser tests showing the bootstrap runs under the production CSP, fragment removal still precedes exchange, Back history is clean, malformed links do not exchange, and no CSP violation or third-party request occurs.
6. A clean non-OneDrive `next build --webpack`, then actual production-server header captures for `/invite`, `/invite/continue`, and malformed/success-shaped API responses. The `/invite` response must be dynamic and not shared-cacheable.
7. Full typecheck, lint, Vitest, maintained database suites, secret scan, and `git diff --check`.

The final release gate remains hosted: preview proxy/header behavior, real cookie persistence/deletion, CSP/referrer/access logs, hosted Supabase JWT/PostgREST, true multi-connection database concurrency, and one fictional invitation acceptance.

## 9. Failure, release, and rollback

- If nonce generation or header propagation fails, invitation use is unavailable; do not fall back to query tokens, script `unsafe-inline`, a weaker CSP, or public caching.
- App/database skew remains fail closed. Complete this source repair and pass local/preview evidence before migration 005 is applied.
- Release application/UI first, verify headers/CSP and fail-closed exchange, then apply migration 005, then run hosted fictional acceptance evidence.
- A rollback disables invitation issuance and repairs forward. It must never restore query-string bearer links, public caching, service-worker fallback, or authenticated execution of the retired raw-token RPC.
- Public AI-search metadata/robots/sitemap changes are independent and must remain unchanged by this repair.
