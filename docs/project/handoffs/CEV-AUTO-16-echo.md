### Verified Retell signing findings

Retell's current security guide specifies the webhook-badged API key, exact raw body and X-Retell-Signature. Its signature format includes a millisecond timestamp and digest; the guide uses HMAC-SHA256 over raw body followed by timestamp, a five-minute freshness check and constant-time comparison. Prefer its SDK helper, then test actual installed helper behavior. Parsing and re-serializing JSON invalidates signing inputs. A Make transformation requires its own authenticated delivery boundary; it cannot reuse a Retell signature for altered bytes. [Retell security guide](https://docs.retellai.com/features/secure-webhook).

Retell documents ten-second acknowledgement and up to three retries. Lifecycle deduplication uses event plus call ID; transfer events need attempt-specific discrimination. Default events are started, ended and analyzed; transfer events exist separately. Agent-level webhook configuration takes precedence over account-level routing. Privacy opt-out still permits sensitive content in webhook payloads, so apply an ingestion allowlist. [Retell webhook specification](https://docs.retellai.com/features/webhook-overview).
