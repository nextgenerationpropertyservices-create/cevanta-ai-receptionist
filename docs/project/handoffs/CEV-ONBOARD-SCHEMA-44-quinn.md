## Security findings

- Public onboarding tables have RLS enabled, no policies and explicit client/PUBLIC privilege revocation. Sensitive profile, escalation, resume and configuration rows are inaccessible even to ordinary owners until guarded read commands exist. Private schema USAGE, table access and helper EXECUTE are revoked; private tables also enable RLS. This is a deliberate closed foundation, not missing permissions to repair by granting broad SELECT.
- Internal revision/settings definer functions are postgres-owned, pinned empty search_path and inaccessible as ordinary callable APIs. The existing tenant UPDATE RLS/grants remain the entry guard. Actual owner/admin changes advance root revision atomically, with metadata-only audit; dispatcher/technician/viewer/foreign owner changes do not affect that tenant. Invalid timezone, overflow and injected root/audit-path failure roll back the tenant change. Existing module SQL suites still pass.
- Contacts, invitation email/token digest, receipts and readiness policy are not put into public projections/audit payloads. Existing audit trigger records entity IDs/action/actor only. Dispatcher gains no global audit access. Invitation token helpers enforce canonical bytes; plaintext token is not stored. Receipt structures contain minimal binding/result fields, composite tenant FKs and immutable history, not cached names/entry/readiness/content.
- Invitation accepted identity/time and immutable recipient/token/tenant fields are retained; reset to pending and conflicting pending roles reject. Recipient UUID storage does not verify Auth identity, and fixtures changing status do not implement authenticated acceptance. Future RPC must independently enforce confirmed current Auth user/email, exact current intended membership, post-wait pending expiry and every replay binding from Atlas42/43.
- JSONB interval aggregates avoid orphan cross-tenant child links; checks enforce endpoints, bounds, overlap and closed-day semantics. Exception identity/tombstone retention and cap are coherent with replay design. Missing seven-day aggregate completion, row-version increments and config invalidation for future config writes remain command responsibilities; ordinary users cannot exploit their absence through direct writes in this foundation.
- Shared parsing rejects injected role/actor/extra fields, malformed numbers, invalid authoritative fields, NUL and invalid contact/date/token formats. Body sizing is parsed JSON size only; future HTTP boundaries still need raw-byte limits. Digest helpers take trusted actor plus normalized input; they neither authorize callers nor replace independently normalized SQL. Supported catalog/representation parity must remain pinned.
