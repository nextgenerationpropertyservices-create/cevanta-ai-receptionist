## Approved security boundaries and implementation prerequisites

- Roles: Owner/admin/dispatcher positive access only under current verified membership. Technician/viewer/anon/removed/demoted denied content, counts, history, summaries and commands. Parent CRM/job visibility never implies draft access. Current role checked independently in server and database; database membership FOR SHARE defines revocation ordering honestly. A permitted transaction already holding the lock may finish before revocation commits; no retroactive cancellation promise.
- Direct bypass: Public table RLS and authenticated SELECT-only grants; no client direct mutation. Private schema/receipt grants and RLS deny client access. Exact authenticated command signatures only, no PUBLIC/anon execute or internal-helper execute. Review views/joins and default privileges in actual migration; opaque cursors must be tenant/filter/order-bound and reauthorized, not treated as bearer access.
- Definer: postgres-owned SECURITY DEFINER may bypass RLS. Authenticated actor, tenant membership/office role, scoped target/parents, state/version and input validation MUST be checked inside every command; server getUser is additional protection, not a substitute for direct RPC checks. Empty search_path, qualified functions including digest resolution, no dynamic SQL, tightly restricted execute and no ordinary service-role client are mandatory. Verify actual owner, pgcrypto schema and grants before execution; stop rather than weaken constraints.
- Parents: Composite tenant/customer/job/location relationships and immutable identities supported. Customerless job rejects; selected job location derived or contradictory location rejected. Trigger and locked parent validation must agree. Deferred lead/equipment/assignee/money input rejects. No cascade deletion of draft/history/receipts and no unrelated CRM/job/lead/calendar mutation.
- Privacy: Private receipt digest is sensitive, not anonymized. No raw notes/content or digest/API receipt projection. Actor/tenant/command/request/target binding and current permission before replay prevent stale privilege and cross-actor disclosure. Submission collision returns conflict, not another actor's saved object. Owner/admin metadata audit access remains as existing policy; dispatcher gains no global audit read. Test new entity metadata cannot leak through denied joins/logs. No current content/version in errors; no raw SQL/input/provider details.
- Concurrency: Consistent membership/tenant/request/submission/aggregate/child ordering, row locks/version comparison, durable receipt and final uniqueness must all exist in real SQL. One-active partial index complements draft serialization. Atomic receipt/audit/business transaction rolls back on unexpected errors; original committed replay version must not be mistaken for current content. No TTL/replay-token resets in this slice. Terminal follow-ups immutable; no reopening or silent duplicate audit.
- Dates: Strict real Gregorian date/year/code-point validation independently in server/SQL. Current valid IANA workspace zone and one trusted instant per read snapshot; invalid configuration fails without browser/UTC fallback. Due labels scheduled-only, past dates permitted, due_on unchanged by settings. Earliest next date-change instant requires DST/discontinuity tests, not24-hour arithmetic. Exact authorized replays survive later invalid timezone without creating fresh work. No reminder execution implied.
