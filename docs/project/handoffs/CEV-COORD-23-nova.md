## Current readiness and exact risks

Not ready for a live booking path from an office UX perspective. Source inventory has no call outcome/operator review route. Dashboard says calls await integration; navigation has no Calls destination. Settings edits business name/trade/time zone only, with owner/admin gating. Design-only integration ports contain call outcomes and handoff states but no runtime verifier, persisted receipt or operator workflow. The internal calendar stores job appointments, shows UTC and explicitly does not check conflicts; its scheduled status is not external-calendar confirmation.

Make22 valid=true means an isolated date interval passed validation. It does not mean a customer, job, appointment or provider event was saved. Its trusted clock is fixed fictional2030; its scenario remains inactive. Risks before live enablement:

1. False success: labeling date validation, webhook receipt, SMS submission or a telephony transfer as a confirmed booking/resolved handoff could mislead caller and office.
2. Time mismatch: workspace settings show a time zone while internal scheduling is UTC; provider date parsing, daylight-saving ambiguity and actual caller/business time must have an approved explicit conversion contract. Never silently substitute current time or a default date for invalid/missing input.
3. Partial effects: external booking might succeed while app persistence or messaging fails. A generic failure plus an unrestricted Retry button can duplicate a booking or message.
4. Lost follow-up: current UI has no queue, assignee, acknowledgement, age/escalation indicator or durable recovery history for failed/uncertain outcomes.
5. Tenant/privacy exposure: UI role gating alone is insufficient. Call references, summaries and linked records need verified tenant access; technicians must not gain broad caller/transcript access through this feature. Provider account identifiers, secrets and raw webhook payloads must not appear in ordinary settings/errors.
6. Unclear integration state: an isolated simulation or configured connection must not be shown as Live/Healthy, nor should inactivity hide pending operator work. Availability and concurrency are unresolved, so a selectable/requested slot must not be presented as reserved.
