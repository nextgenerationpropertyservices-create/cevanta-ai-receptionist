## Security decision and resolved requirements

1. Current identity and office membership precede receipt access and response. The server's verified getUser check supplements the RPC's independent authenticated subject and locked current owner/admin/dispatcher membership. Tokens never authorize access. Removed/demoted members cannot replay earlier success; tenant-scoped current target and immutable parent bindings remain mandatory. Definer functions must enforce these predicates explicitly because their owner can bypass RLS.
2. All six commands acquire membership, tenant, request advisory, optional creation submission advisory, then ordered aggregate/child or creation-parent locks. Tenant FOR SHARE is unconditional, including replay. Timezone is read under that lock but validated only for new follow-up work after receipt miss. No branch discovers replay and then takes a late tenant lock. Draft commands do not need a valid timezone. This resolves the previously conditional order.
3. Receipt lookup follows both applicable advisory locks and uses exact tenant/actor/command/request identity with a fresh statement. Digest binds normalized original arguments, expected versions and contract version. Target/result checks are command-specific: draft create uses its own committed draft; follow-up create checks the input draft and receipt result child; existing-target commands require the exact input target and current child-parent relation. Create replay does not recompute mutable parent choices. Other actors' receipts are not consulted to reveal ownership or content.
4. Authorized replay skips current business preconditions, not authorization or receipt integrity. Later versions, terminal state, replacement active follow-up and invalid current timezone cannot invalidate the original committed response. Original receipt version is returned only after positive/in-range integrity checks; it is not current content. Missing/inaccessible targets return unavailable; contradictory private receipt returns generic retryable_failure without mutation or details. No new audit, receipt, timestamp or business write on replay.
5. Safe errors and minimal replay prevent private disclosure: no original colliding target, notes, title, digest, canonical input, actor history, current content or foreign existence details. Current UI detail must come from a separate authorized read; configuration_error on that read does not undo committed replay. Office-only RLS/grants, private receipt denial and existing owner/admin audit visibility remain unchanged. No financial, sending, acceptance, payment, reminder, provider or calendar effect is added.
