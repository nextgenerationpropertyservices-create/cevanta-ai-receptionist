- Validate UUIDs, allowed field lengths/enums, approved lifecycle transitions, parent and assignee chains, revision precondition and final business inputs server-side. Do not trust client totals, role, tenant or acceptance actor. After decisions, use agreed exact decimal/minor-unit representation and rounding with database bounds; never invent currency, tax rate, precision, negative-item/discount rules or floats as monetary authority. Prevent unknown identity/privilege injection; immutable revision snapshot rules need Atlas review.
- Related estimate/items/state changes and metadata audit must be atomic. Existing independent form writes do not establish multi-row estimate transaction correctness. Prefer an Atlas-reviewed transactional command, with authorization inside the transaction and restricted grants, rather than sequential writes leaving partial items/totals. No totals or customer text in default metadata audit/logs. Keep role checks for audit reads.
- Durable create/send/reminder/accept-operation keys need tenant scope, operation/revision binding and conflict semantics. A new random key per retry defeats protection; memory-only dedupe is not durable. Failed transaction remains retryable; provider timeout after success must reconcile before resend. Preserve actual actor/time/source without recording raw private payloads.
- Safe errors distinguish invalid inputs, unavailable/not-authorized record, stale revision and uncertain delivery where useful, without disclosing foreign records, database/provider details, recipient contact data or credentials. Preserve Next control-flow exceptions; revalidate affected UI only after committed success. Frontend hiding cannot authorize a transition.
