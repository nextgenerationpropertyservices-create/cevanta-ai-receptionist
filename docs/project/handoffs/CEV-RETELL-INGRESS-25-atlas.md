- Known limitations / exact architecture gaps:
  1. **Full request path is not isolated:** current proxy matcher includes this route; configured proxy calls Auth before handler dispatch, including when the handler would disable POST. Therefore the new modules are no-network, but a full configured application request can perform an unrelated Auth request. Direct-handler tests do not prove request raw-byte preservation through deployment/proxy, route availability or absence of all network activity. Before any hosted or full-server acceptance, assign proxy/operations ownership and review narrowly scoped machine-ingress handling without weakening ordinary user authorization.
  2. **Local compatibility only:** call_/agent_ prefix/character limits and64KiB envelope cap are stricter minimum-fixture policies, not established universal provider constraints. No actual selected-agent signed payload was examined; large analyzed calls can exceed the cap. Safely establish identity shapes and delivery representation before widening limits or claiming operational compatibility.
  3. **No durable replay or tenant authorization:** within-window repeats are intentionally reverified and discarded. The five-minute delivery window does not authorize current tenant/agent revision, prevent duplicate effects, constrain business-event age or enforce out-of-order transitions. Strict canonical signature timestamp handling is more restrictive than arbitrary leading-zero forms in the reference helper; test actual signed fixtures before compatibility claims.
  4. **Hosting protections absent:** no distributed rate control, read deadline, environment isolation/retention evidence or infrastructure log review. Bound memory does not prevent slow requests. Prototype flags are environment configuration rather than caller-selectable fields, but development hosting still needs a separate access/operations review. Tests cannot guarantee a configured secret is fictional; do not provide real keys or connect existing callbacks.
  5. **Success discards the event:** returning200 acknowledges verification only and stores nothing. Repointing an operational callback could irrecoverably lose events and stop provider retries. It must stay a fictional local endpoint until a reviewed durable receipt/processing contract replaces that behavior.
