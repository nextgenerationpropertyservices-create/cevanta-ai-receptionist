## Contract clarification needed for later UI

Atlas's table/state/result design is sufficient for design-fit approval but not a published UI read contract. Before Nova implementation, Atlas/Blake must publish authorized list/detail shapes, current draft/follow-up versions, active-task/history projection, safe parent labels, workspaceToday/timezone, and stable conflict categories. Decide list pagination/filtering and safe missing-parent behavior; do not expose private receipts or audit payloads to the browser. Confirm whether scheduled follow-up note edits use RescheduleFollowup with unchanged date or a separate bounded update command; UI must not invent a disconnected save action.

Creation/retry semantics also need an explicit UI-safe result rule: an earlier replayed save may coexist with newer content. Success copy must say the operation was already saved and then display freshly fetched current content. A changed request under the same token must remain a conflict, never look like a generic validation error encouraging an identical failing retry. An unavailable current record must not leak prior content through replay results.
