## API and contract changes

Shared types define strict config envelopes, all seven exact payloads, resume, three-state invitation success and safe failure allowlists. Saved owner/admin snapshot separates authority from contacts; dispatcher snapshot excludes contacts, invitations, actors, readiness diagnostics and counts; technicians/viewers use existing workspace projection. Future reads must use a coherent snapshot. Pending readiness is fixed not_evaluated/setup_policy_pending, booking blocked, release not_evaluated, hostedReady/providerConnectionAuthorized false; no completion policy is inferred.

Validators reject unknown/missing keys, non-actual booleans/integers, invalid UUIDs/text/Unicode/NUL, bounds, invalid dates, overlapping hours and duplicate item IDs. ASCII edge trim and Unicode code-point length match PostgreSQL; blank nullable contact normalizes null, required tenant fields never do. Supported email is bounded ASCII dot-atom plus DNS-style domain (no quoted/Unicode mailbox), local<=64/domain labels<=63/total<=254. Contact email case preserved; private invite recipient email lowercase. Phone uses explicit international + followed by2–15 digits, first digit1–9; no default country or invented local conversion. Issuance comparison/delivery policy remains excluded. These are syntactic representations, not verification of reachability.

Token validation accepts exactly canonical43-character unpadded base64url representing32 bytes. SQL token_bytes decode/re-encode and token_digest SHA256 agree with Node; only digest is stored. No token logging/plaintext storage. Route logging/redaction and fragment/session flow remain later assignments.

Digest serialization: UTF-8 sorted ASCII-key JSON with no spaces; normalized arrays ordered weekday/start/position+id (equal null-ID items preserve input order). SQL canonical_json receives independently normalized JSONB with numeric fields rebuilt as integers, **not raw body/jsonb::text**. Shared configurationDigestDocument binds onboarding-v1 + exact command + verified actor + full normalized input (tenant/request/precondition/payload); resumeDigestDocument binds version/actor/input. invitationDigestDocument binds version/invite_accept/tenant/verified actor/request/canonical lowercase hex SHA256 token digest, never original token. SHA256 these bytes; receipt stores digest only. Do not hash raw browser JSON or trust a client-supplied digest/actor. Server must independently normalize, verify tenant target ownership, enforce raw128KiB transport limit before parsing, and reauthorize before receipt replay. Current parsed-body validator bounds its serialized size; it is not a raw HTTP byte limiter.

Receipt result mapping: setup derives public result id from tenant_id; exception uses result_id (null for absent removal), immutable target_date and original revision; resume uses resume_id and original version; invitation uses invitation_id/intended_role/original accepted_at. No contact payload, names, email, tokens, entry or readiness is stored. Later invitation response recomputes current authorized workspace projection and entry; accepted receipt cannot restore membership. New successful already_accepted requests must each insert a receipt; identical replay writes nothing. Later command must enforce all42/43 locks, current confirmed email and exact intended membership, post-wait pending expiry, safe conflicts and atomic membership/audit/receipt/projection rollback.
